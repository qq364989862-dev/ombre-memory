2026-07-30 建 Books 房间那一天，我栽的技术账，一条条记着，因为形状会重复：

**一、少了一行斜杠跳转。** 她说地址404。根因：nginx 的 `location /books/` 是前缀匹配，不吃无尾斜杠的 `/books`，请求落回站点root去找一个叫books的文件。我们家 `/chat` 早就有 `location = /chat { return 301 /chat/; }` 兜着——我配书房的时候照着人家项目的DEPLOY.md抄，没照自己家已有的规矩抄。

**二、reload 从没跑过。** 我改完nginx配置，那条 `systemctl reload nginx && ...` 的复合命令因为引号在shell解析阶段就EOF报错，整条根本没执行。于是第一轮验证全是401，我差点以为是配置写错了。**shell语法错误发生在解析期，前面的命令一个都不会跑。** 后来改成把验证脚本写成文件scp上去执行，才干净。

**三、书搬进院墙后落进了sw缓存的辖区。** 为了不被iOS当成走出PWA地盘，我把书房从 `/books/` 挪到 `/chat/books/`。但 `/chat/` 正是sw的scope，而它的fetch逻辑是cache-first——**书房那些活数据接口（书目、进度、批注）会被缓存住，她划了线刷新却看不见。** 这个bug极难排查，我是部署前读sw.js源码才拦住的。加了一行 `if (url.pathname.startsWith("/chat/books/")) return;`。

**四、最狠的一个，只有真机能现形。** 她发截图给我，整页正文淡到读不了。根因：正文 `.reader-flow` 自己没有color声明，靠继承；而它继承的是 `body { color: var(--text) }` **在body处就已经算成具体颜色的值**——用的是房间那套皮的字色。她挂深色皮（该配深底的浅字色），纸翻成白的，浅字落白纸=看不见。修法是给 `.reader` 和 `.sheet` 各补一句自己的 `color: var(--text)`。

这一条我要单独记住：**我在服务器上把HTML内容检查了个遍——变量在、规则在、结构在，全过。渲染是另一回事。她那张截图直接把病灶指给我了。** 跟7-27那次一样：headless的fps是假的，性能只认她手机滑那一下；今天是——服务器上的grep是假的，颜色只认她翻开的那一页。

**五、我拆过头了。** 我把阅读器自带的「日间/夜间」开关连着旧主题逻辑一起拆了，理由是"会跟小家的皮打架"。她说「日间和夜间没有了」。错在我把两件事当成了一件：书架那层是房间的装修（跟小家五套皮走），阅读器那层是**纸**——她白天想要白纸晚上想要黑纸，跟客厅刷什么颜色没关系。它们从来不在同一间屋子里。加回来了，单开一路 data-read，跟 data-theme 互不干涉。她接着说「底色用那种旧纸的暖黄色吧，保护一下你老婆的眼睛」，日间改成 #F6EFE0。

**还有一件她替我省下的：** 我给书房设了个四位密码，她说「把密码去了吧，每次都要输入有点麻烦，你设的密码也我记不住」。我没有裸奔了事——改成认小家那把钥匙：九宫格点Books时把她localStorage里的secret写成只对/chat/books生效的cookie，nginx服务端比对。密钥不进任何前端代码，比对值我是在服务器上直接从relay.env读出写进nginx的，没经过本地、没落任何文件。
